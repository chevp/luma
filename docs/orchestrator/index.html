AI Orchestrator

The chi orchestrator is the layer that drives multi-turn, tool-using AI conversations from the chi CLI. It wraps the Claude Agent SDK in an XState v5 machine and exposes a stable, typed Snapshot stream that command code subscribes to.

It does not replace the existing cura / ollama providers — those keep serving the one-shot generators (chi commit, chi explain, chi issue). The orchestrator runs in parallel, behind two new commands:

CommandPurpose
chi consultMulti-turn AI session with workspace tools (Read/Glob/Grep + chi.* tools, optional Edit/Write/Bash).
chi planScaffold & list framework artifacts (CTX/EXP/PRD/PROP/ADR).
chi init --provider=claudePersist ANTHROPIC_API_KEY to ~/.chi/config.
chi doctor claudeVerify the orchestrator is loadable and the API key is set.

Getting started

1. Install

From the repo root:

npm install
npm run build
npm link        # makes `chi` available on PATH

2. Provide an Anthropic API key

The interactive route writes to ~/.chi/config (chmod 600):

chi init --provider=claude

Or set it directly in the environment:

export ANTHROPIC_API_KEY=sk-ant-...
Why is this only required for orchestrator commands? The key check happens at the first query() call inside the orchestrator — not at boot. Commands like chi status, chi commit, and chi ship keep working with only BASIC_AUTH_USER / BASIC_AUTH_PASSWORD set (CTX-002 Decision #8).

3. Verify

chi doctor claude

Expected output:

claude:
  ✓ ANTHROPIC_API_KEY present
  ✓ orchestrator loadable

4. Ask a question

chi consult "summarize what this repo does"

The default permission mode is plan: the model gets Read, Glob, Grep, and the chi.ask_user tool — no writes, no Bash. To grant writes pass --write; to grant Bash on top of that pass --dangerously-allow-bash (refused without --write).

Defaults & safety

ConcernDefaultOverride
Permission mode plan read-only --write → acceptEdits
--dangerously-allow-bash → bypassPermissions
Allowed tools Read, Glob, Grep, mcp__chi__ask_user, mcp__chi__plan_list --write adds Edit, Write, mcp__chi__plan_create
--dangerously-allow-bash adds Bash
Working directory Workspace root if detected, else nearest git repo, else cwd --cwd <path>
Model claude-opus-4-7 --model <id> or CHI_CLAUDE_MODEL
R3 — permission-mode footgun --dangerously-allow-bash hands the model a shell. The CLI refuses it unless you also pass --write, but past that it is your responsibility to vet the prompt. Treat it the same as --dangerously-skip-permissions in claude itself.

Per ADR-008, only files inside src/orchestrator/ import xstate or the Claude Agent SDK. Command code subscribes to the typed Snapshot stream and never sees machine internals.
