chi consult

chi consult opens a multi-turn AI session backed by the claude-agent orchestrator. The model receives your question plus a tool surface (workspace reads, optional writes, optional bash) and runs until it produces a final answer.

Synopsis

chi consult [<question>] [options]

If <question> is omitted, you'll be prompted on stdin.

Options

FlagEffect
--writeSwitch permissionMode to acceptEdits and add Edit, Write, and mcp__chi__plan_create to the allowed-tools list.
--dangerously-allow-bashSwitch to bypassPermissions and add Bash. Refused unless --write is also passed.
--model <id>Override CHI_CLAUDE_MODEL for this run. Default: claude-opus-4-7.
--cwd <path>Override the workspace/repo resolver. Use this when consulting about a directory other than the one you're in.
-h, --helpPrint help and exit 0.

Permission modes

ModeToolsUse when
plan (default) Read, Glob, Grep, mcp__chi__ask_user, mcp__chi__plan_list Asking questions, exploring, summarizing, drafting answers without touching the tree.
acceptEdits + Edit, Write, mcp__chi__plan_create Letting the model rewrite files in place — refactors, plan creation, doc edits.
bypassPermissions + Bash You explicitly want the model to run shell commands. Pair with version-control discipline.

Workspace mode vs. repo mode

Before invoking the SDK, chi consult calls resolveWorkspaceRoot() to choose options.cwd:

  • Workspace mode wins when an ancestor of cwd contains a CLAUDE.md mentioning "Workspace Mode" or "chevp-workflow" and contains sub-directories that are themselves git repos. The orchestrator then runs from that ancestor — useful for cross-repo questions.
  • Repo mode kicks in otherwise: the resolver walks up to the nearest .git and uses that as the cwd.

The detected mode is printed to stderr at the start of every consult run (e.g. (repo mode at /Users/me/proj, permission=plan)).

The chi.* tool surface

The orchestrator registers a small in-process MCP server named chi with three tools the model can call directly. They appear in allowedTools as mcp__chi__<tool>.

ToolSchemaBehavior
mcp__chi__ask_user { question: string, options?: string[] } Calls the configured AskUserHandler (readline by default), reads the answer from the terminal, returns it as a tool_result.
mcp__chi__plan_list { type?: "CTX"|"EXP"|"PRD"|"PROP"|"ADR" } Lists framework artifacts under context/plans/ and context/adr/.
mcp__chi__plan_create --write { type, title } Scaffolds a new framework artifact with conformant frontmatter and returns the new path. Only enabled with --write.

Examples

Read-only summary

chi consult "what does this repo do? cite three relevant files."

Draft a new ADR

chi consult --write "draft an ADR for adopting pino as a logger.
write it to context/adr/ via the chi.plan_create tool."

Run shell + write changes

chi consult --write --dangerously-allow-bash \
  "find unused exports with ts-unused-exports and remove them"

Cross-repo consult from a workspace root

cd ~/workspace
chi consult "compare error handling across all sub-repos under tools/"

Exit codes

CodeMeaning
0The orchestrator reached the done state (model emitted a final answer).
1Argv error, missing ANTHROPIC_API_KEY, refused flag combination, or the orchestrator transitioned to terminated.error.
2The user cancelled the run (USER_CANCELLED event).

Environment

VariableEffect
ANTHROPIC_API_KEYRequired. Read from env or ~/.chi/config via the anthropic_api_key key.
CHI_CLAUDE_MODELDefault model id. Overridden by --model.
CHI_CLAUDE_PERMISSION_MODEReserved for future use; today the CLI flags are authoritative.
How the model sees the workspace The Agent SDK's built-in Read/Glob/Grep tools are sandboxed to options.cwd. There is no way for the model to escape that root — --cwd is the only knob.
