Architecture

This page is the canonical reference for how the orchestrator is wired, what each module owns, and how a single chi consult turn flows through the system. The authoritative spec is CTX-002; this document is its visual companion.

Layering

src/
  provider/                 ← unchanged: cura, ollama (one-shot generate())
    types.ts
    cura.ts
    ollama.ts

  orchestrator/             ← claude-agent only (ADR-007 + ADR-008 carve-outs)

    sdk-actor.ts            ← fromCallback: SDK iterator → machine events

Architectural rule (per ADR-008): only files inside src/orchestrator/ import xstate or @anthropic-ai/claude-agent-sdk. Command files subscribe to the typed Snapshot stream and never see the underlying machine or SDK types. This makes the state-machine library swappable without rewriting commands.

State machine

                       ┌─────────┐
                       │  idle   │
                       └────┬────┘
                  START(prompt, options)
                            ▼
                   ┌────────────────┐
                   │    running     │     ◄─── parent state
                   │  (initial:     │           (sdkActor invoked here)
                   │   receiving)   │
                   └───┬────────────┘
        ┌──────────────┼──────────────┐
        ▼              ▼              ▼
 receivingText   executingTool        ─
        │             │
        │    ┌────────┼────────┐
        │    ▼        ▼        ▼
        │ builtIn  chiAsk  writeAttempt   ◄─── R3 violation marker
        │  Tool    User     (final)
        │    │        │
        └────┴────────┘
                    │
        RESULT(stopReason)
                    ▼
              ┌───────────┐
              │   done    │   ◄─── final
              └───────────┘

Cross-cutting (any non-final state):
  ERROR(e)        → terminated.error
  USER_CANCELLED  → terminated.userCancelled

The machine is defined once in src/orchestrator/state-machine.ts using XState v5's setup({ types: ... }).createMachine(...) API for compile-time exhaustiveness. Adding a new state — for instance pausedForPermissionPrompt when an interactive permission callback ships — is a one-place edit.

Why writeAttempt is final

Under permissionMode: "plan", the SDK should never let the model emit a tool_use for Edit, Write, or NotebookEdit. If it does anyway, that is risk R3 from CTX-002 firing. The machine routes such events to executingTool.writeAttempt, a final substate — the parent running state therefore blocks further input, command code can detect the violation, and the run terminates with a loud error instead of silently mutating files.

Snapshot — the typed boundary

Commands subscribe to a stable Snapshot view, not to xstate's internal snapshot: 

type SnapshotState =
  | "idle"
  | "running.receivingText"
  | "running.executingTool.builtInTool"
  | "running.executingTool.chiAskUser"
  | "running.executingTool.writeAttempt"
  | "done"
  | "terminated.error"
  | "terminated.userCancelled";

interface Snapshot {
  state: SnapshotState;
  lastAssistantText?: string;
  pendingToolName?: string;
  pendingQuestion?: string;
  tokens?: { input: number; output: number };
  error?: { message: string; cause?: unknown };
}

Two consequences:

  • Renderers can drive a CLI, a TUI, or the web console off the same data.
  • Swapping XState for an in-tree FSM (ADR-008 Alternative A) needs no command-side change.

Lifecycle of a single turn

  1. User runs chi consult "...".
  2. commands/consult.ts parses argv, picks permissionMode + allowedTools, and resolves cwd via workspace.resolveWorkspaceRoot().
  3. It calls getOrchestrator("claude-agent").start(opts, prompt).
  4. The facade verifies ANTHROPIC_API_KEY (throws MissingAnthropicKeyError on miss), assembles the chi MCP server, and starts an actor = createActor(orchestratorMachine).
  5. The machine enters running and invokes sdkActor, which begins iterating the SDK's async stream.
  6. Each SDK message becomes one event:
    • assistant with text → TEXT → running.receivingText updates lastText.
    • assistant with tool_use → TOOL_USE → guards route to builtInTool / chiAskUser / writeAttempt.
    • result → RESULT → final done.
    • Thrown error → ERROR → terminated.error.
  7. Every state change fires a fresh Snapshot for subscribers; the consult command prints assistant text to stdout and tool transitions to stderr.
  8. run.done resolves with the final snapshot; the command maps that to an exit code (0/1/2).

The SDK actor

sdk-actor.ts is the only piece of glue between the SDK iterator and the machine. It is intentionally tiny — H4 in CTX-002 ("≤ 40 LoC of glue") lives or dies on this file staying small. The cleanup function it returns flips a cancelled flag so the loop bails on its next yield when the machine stops or a USER_CANCELLED arrives.

Why this architecture?

DecisionTrade-offADR
High-level Claude Agent SDK over hand-rolled @anthropic-ai/sdk One new runtime dep vs. ~1500–2500 LoC of security-sensitive tool-loop code we'd own. ADR-007
XState v5 over imperative for await { switch } if Explicit, exhaustive state, devtools-ready, swappable. Costs one more dep. ADR-008
Orchestrator above Provider, not inside it cura / ollama stay one-shot generators. Orchestrator behavior never leaks into providers that can't support it. CTX-002 H1
Live in src/orchestrator/, not a separate package No premature API design. Extract when a second non-wrapper consumer materializes. CTX-002 §Out of scope
permissionMode: "plan" by default Read-only by default; users opt in to --write and --dangerously-allow-bash. CTX-002 §R3

Kill criteria worth remembering

If any of these fire, this whole design re-opens:

  • The SDK refuses to mix a built-in tool with a custom in-process tool in the same query() call. → fall back to the low-level SDK + hand-rolled loop.
  • permissionMode: "plan" performs writes anyway. → chi consult's safety story is unimplementable, escalate.
  • XState v5 ships breaking changes more than once per quarter for two consecutive quarters. → migrate to ADR-008 Alternative A (in-tree FSM).
  • Combined node_modules footprint exceeds 60 MB. → "small CLI" identity is broken; revisit ADR-003 narrow exceptions.
