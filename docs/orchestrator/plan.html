chi plan

chi plan scaffolds and lists framework artifacts — CTX, EXP, PRD, PROP, and ADR documents that the chevp-ai-framework uses to govern non-trivial work (G1 Context → G2 Exploration → G3 Production).

The command is a thin local helper: it does not call the orchestrator and does not require ANTHROPIC_API_KEY.

Layout

TypeFolderWhat it represents
CTXcontext/plans/G1 — context plan / problem framing
EXPcontext/plans/G2 — exploration / prototype
PRDcontext/plans/G3 — production design / acceptance criteria
PROPcontext/plans/Lightweight proposal (deferred work)
ADRcontext/adr/Architecture decision record

Subcommands

chi plan new

chi plan new <CTX|EXP|PRD|PROP|ADR> "<title>"

Behavior:

  1. Resolves the nearest git repo via resolveRepoRoot().
  2. Picks the right folder (context/plans/ or context/adr/) — creating it if needed.
  3. Computes the next NNN by scanning existing files of the same type.
  4. Slugifies the title and writes the file with framework-conformant frontmatter:
---
id: CTX-003
type: CTX
status: proposed
proposed-by: human
proposed-at: 2026-05-11
supersedes: —
related: —
---

# CTX-003 — your title

## Context

(write context here)

## Decision

(write the decision here)

## Consequences

(write consequences here)

chi plan list

chi plan list [<type>]

Lists every framework artifact under the resolved repo, prefixed with its status: from frontmatter. Filter by type with the optional positional argument:

chi plan list ctx
chi plan list adr

Examples

Start a new context plan

$ chi plan new CTX "evaluate alternative state-machine libs"
✓ created /Users/me/proj/context/plans/CTX-003-evaluate-alternative-state-machine-libs.md

List only ADRs

$ chi plan list adr
  accepted   /Users/me/proj/context/adr/ADR-001-language-and-runtime.md
  accepted   /Users/me/proj/context/adr/ADR-007-claude-agent-sdk-exception.md
  proposed   /Users/me/proj/context/adr/ADR-010-pino-logging.md

Programmatic equivalents

The orchestrator exposes the same operations as MCP tools that chi consult can call directly:

CLITool
chi plan newmcp__chi__plan_create (only enabled with --write)
chi plan listmcp__chi__plan_list (always enabled)
Why repo-scoped, not workspace-scoped? Plans live alongside the code they govern. A consult run from ~/workspace resolves to workspace mode for cross-repo questions, but a plan list from inside tools/chi should never spill into other repos' artifacts. resolveRepoRoot() enforces this — it stops at the nearest .git.
